# LexiFlow V2 / V3 产品需求文档（PRD）

> 产品定位：面向桌面阅读、写作与开发场景的本地优先翻译工具。  
> 核心价值：低延迟、隐私、本地模型、自然翻译，以及可理解、可校正的双语阅读体验。  
> 文档用途：用于产品评审、技术设计和 Coding Agent 分阶段执行。

---

## 0. 修订说明

- 将“句子级对照”统一调整为“句段级对照”；
- 明确句段是按句子和语义分句形成的稳定片段，不是视觉换行；
- 原文由本地程序切分并生成 segment ID，LLM 仅按 ID 翻译；
- V2/V3 不再开发逐词或短语级专用对齐器；
- 删除专用对齐模型、对齐缓存、对齐测试和相关资源要求；
- 短语级语义对齐降为远期实验项，不进入正式版本范围；
- 选中单词或短语时，采用“句段联动高亮 + 词典/上下文解释”。

# 2. 产品背景

LexiFlow 当前已经具备基础翻译闭环，但翻译结果仍以“输入文本 → 输出文本”为主，缺少传统翻译软件已经验证过的阅读辅助能力，例如：

- 单词和短语释义；
- 原文与译文对照；
- 历史记录和收藏；
- 发音、复制、替换等快捷操作；
- PDF 复制文本清理；
- 截图和文档翻译。

同时，传统翻译软件通常无法充分利用 LLM 的上下文理解、局部改写、术语约束和自然语言解释能力。

因此，后续版本不应简单复制传统翻译软件，而应形成两层能力：

1. **基础翻译体验层**：补齐字典、对照、历史、清理等成熟能力；
2. **LLM 增强层**：增加局部重译、术语表、翻译配置、截图和文档工作流。

# 3. 产品原则

## 3.1 本地优先

- 默认优先调用本地模型和本地数据；
- 翻译历史、词典缓存、术语表默认保存在本机；
- 远程服务必须明确展示并允许用户关闭；
- 不因增强功能强制上传完整文档或上下文。

## 3.2 快速优先

- 用户选中文本后，界面必须立即反馈；
- 基础翻译不应等待字典或扩展解释完成；
- 高成本能力采用按需调用、延迟生成和本地缓存；
- 不允许为了结构化输出显著拖慢核心翻译。

## 3.3 结果可理解

LexiFlow 不只展示译文，还应帮助用户回答：

- 这句译文对应哪句原文？
- 这个单词在当前语境中是什么意思？
- 为什么这样翻译？
- 是否存在更正式、更自然或更直译的表达？

## 3.4 结果可控制

用户应能够：

- 固定术语翻译；
- 局部重新翻译；
- 选择语气和风格；
- 保留原文格式；
- 明确哪些内容不应翻译。

## 3.5 渐进增强

- 默认界面保持简洁；
- 详细词典、上下文解释和备选译法按需展开；
- 浮窗承担“快速查看”，主窗口承担“深入处理”。

# 5. V2 PRD：翻译体验补全

## 5.1 V2 目标

V2 重点解决三个问题：

1. 用户看到了译文，但不容易确认原文和译文的对应关系；
2. 用户遇到单词或短语时，仍需要打开其他词典；
3. 翻译结果缺乏历史、收藏、复制和文本清理等基础工作流。

## 5.2 V2 非目标

V2 暂不实现：

- 单词背诵和完整学习系统；
- 云端账号同步；
- 复杂 Word、PPT 排版还原；
- 图片内译文覆盖；
- 逐词或短语级精细语义对齐；
- 多 Agent 翻译或复杂推理流程；
- 社区词典和用户内容分享。

## 5.3 V2 功能范围

### P0-1：结构化句段翻译结果

#### 需求说明

翻译接口不再只返回一段字符串，而应返回可渲染、可关联的句段数据。这里的“句段”是按句子和语义分句形成的稳定片段，不是随窗口宽度变化的视觉行。

#### 推荐数据结构

```ts
interface TranslationResult {
  requestId: string;
  sourceText: string;
  targetText: string;
  sourceLanguage: string;
  targetLanguage: string;
  segments: TranslationSegment[];
  modelInfo: ModelInfo;
  createdAt: number;
}

interface TranslationSegment {
  id: string;
  source: string;
  target: string;
  sourceStart: number;
  sourceEnd: number;
  targetStart?: number;
  targetEnd?: number;
}

interface ModelInfo {
  provider: string;
  model: string;
  durationMs: number;
  inputTokens?: number;
  outputTokens?: number;
}
```

#### 实现要求

- 短文本允许只有一个 segment；
- 长文本由本地程序优先按句号、问号、感叹号、分号、冒号和自然段切分；
- 对过长句子可在逗号或从句边界继续拆分，但不得机械按固定字符数截断；
- 应保护小数、缩写、科学计数法、URL、代码、文件路径和括号内容，避免错误切分；
- 原文分段和 segment ID 由本地程序生成，LLM 只负责按 ID 返回对应译文，不负责重新划分原文；
- segment ID 在一次翻译结果中稳定；
- 原始全文和分段结果必须同时保留；
- 前端不得通过模糊字符串搜索建立对应关系；
- 模型结构化输出失败时，必须回退到普通译文展示。

#### 建议切分粒度

- 中文单个句段建议约 15～50 个汉字；
- 英文单个句段建议约 8～30 个词；
- 超出建议长度时优先按语义边界拆分；
- 无可靠切分点时允许保留完整长句，稳定性优先于片段长度。

#### 推荐处理流程

```text
原始文本
  ↓
本地文本清理与句段切分
  ↓
生成稳定 segment ID
  ↓
LLM 按 segment ID 翻译
  ↓
前端按 ID 完成双向联动
```

#### 验收标准

- 任意正常翻译请求均能展示译文；
- 结构化解析失败不会导致界面空白；
- 中英文段落顺序正确；
- 同一文本片段多次出现时不会高亮错误位置。

### P0-2：句段级中英文联动对照

#### 需求说明

用户悬停、点击或选中某个原文句段时，对应译文同步高亮；反向操作同样成立。联动基于稳定的 segment ID，而不是基于文本在界面中的自动换行位置。

#### 交互规则

- 鼠标悬停：临时高亮对应句段；
- 单击：锁定高亮；
- 再次点击空白区域：取消锁定；
- 键盘方向键：在句段之间移动焦点；
- 选中局部文本：至少高亮其所在句段的对应译文；
- 长文本滚动时，可选择是否自动滚动到对应句段。

#### 展示模式

1. **默认模式：上下结构**
   - 原文区域在上；
   - 译文区域在下；
   - 适合现有划词翻译浮窗。

2. **逐句段对照模式**
   - 每条原文下方紧跟对应译文；
   - 适合中等宽度窗口。

3. **双栏对照模式**
   - 左侧原文，右侧译文；
   - 仅在主窗口或足够宽的浮窗中启用。

#### 验收标准

- 悬停后 50ms 内完成前端高亮；
- 原文与译文可双向联动；
- 高亮不改变文本布局；
- 句段在不同窗口宽度下换行后仍能完整高亮；
- 复制文本时不携带高亮样式或隐藏标记；
- 不引入专用词语对齐模型、ONNX Runtime 或额外模型权重；
- 相比普通翻译只允许增加少量结构化输出和前端渲染成本；
- 结构化结果失败时必须回退为普通全文展示。

#### 技术边界

V2 不承诺逐词或逐短语的一一对应。用户选中单词或短语时：

1. 高亮其所在句段及对应译文句段；
2. 打开词典或上下文解释；
3. 不尝试推断译文中的唯一对应词。

### P0-3：轻量字典

#### 需求说明

用户双击或选中单词、短语后，展示轻量字典卡片，避免离开 LexiFlow 查询。

#### 第一版展示内容

- 查询词；
- 音标；
- 美式或英式发音；
- 词性；
- 2～4 条常用释义；
- 常见词形变化；
- 当前上下文中的含义；
- 2～5 个常见搭配；
- 复制、收藏、发音按钮。

#### 数据来源分层

**基础词典层**

用于：

- 音标；
- 词性；
- 基础释义；
- 词形；
- 固定搭配。

优先使用稳定的本地词典数据或可缓存的数据源。

**LLM 上下文层**

用于：

- 当前句段中的具体含义；
- 该词为什么这样翻译；
- 相近表达的区别。

LLM 内容必须与基础词典内容分区展示，避免混淆。

#### 交互要求

- 选中单词后先展示 loading 占位；
- 基础词典结果优先出现；
- LLM 上下文解释异步补充；
- 点击卡片外部关闭；
- 卡片不能遮挡当前选中文本；
- 支持通过快捷键固定卡片。

#### 验收标准

- 单词和常见短语都可以查询；
- 无结果时展示明确状态；
- 不因字典请求阻塞翻译；
- 同一个词的结果可以本地缓存；
- 离线状态下基础词典仍可使用，前提是本地词典已经安装。

### P0-4：历史记录

#### 需求说明

所有翻译结果统一进入本地历史记录，用户可检索和复用。

#### 历史字段

```ts
interface TranslationHistoryItem {
  id: string;
  sourceText: string;
  targetText: string;
  sourceLanguage: string;
  targetLanguage: string;
  mode: "translate" | "naming";
  sourceApp?: string;
  modelProvider: string;
  modelName: string;
  createdAt: number;
  isFavorite: boolean;
}
```

#### 功能要求

- 按时间倒序展示；
- 支持搜索原文和译文；
- 支持复制、重新翻译、删除、收藏；
- 支持按翻译/命名筛选；
- 支持清空全部历史；
- 支持隐私设置：
  - 不保存；
  - 保存 7 天；
  - 保存 30 天；
  - 永久保存；
  - 退出应用时清除。

#### 验收标准

- 应用重启后历史仍存在；
- 搜索能够匹配原文和译文；
- 删除操作立即生效；
- 用户关闭历史保存后，不再产生新记录；
- 清空操作需要二次确认。

### P0-6：输入文本自动清理

#### 需求说明

从 PDF、网页、终端和代码编辑器复制的文本经常包含异常换行、断词或多余空格。翻译前应自动清理，但必须允许用户查看和关闭。

#### 清理能力

- 合并段落内部的硬换行；
- 保留真正的段落间隔；
- 合并英文断词：

```text
artifi-
cial
```

恢复为：

```text
artificial
```

- 清理连续空格和不可见字符；
- 修正常见全角/半角混用；
- 识别代码块、URL、邮箱和文件路径，避免误处理；
- 保留 Markdown 标题、列表和代码块结构。

#### 设置项

- 自动清理文本：开/关；
- 保留原始换行：开/关；
- 保护代码块：默认开启；
- 翻译前预览清理结果：可选。

#### 验收标准

- 普通 PDF 复制文本可恢复为可读段落；
- 不合并独立列表项；
- 不破坏 URL、路径和代码；
- 用户可以查看原始文本；
- 自动清理失败时使用原始文本翻译。

## 5.4 V2 核心页面

### 5.4.1 划词翻译浮窗

建议结构：

```text
[翻译] [技术] [命名]                         [固定] [关闭]

原文
------------------------------------------------
译文

[复制] [双语] [发音] [收藏] [主窗口]
```

选中单词后显示浮层字典，不直接挤压主翻译区。

### 5.4.2 主窗口翻译页

建议区域：

- 顶部：语言方向、翻译配置、模型状态；
- 左侧或上方：原文输入；
- 右侧或下方：译文；
- 工具栏：复制、对照模式、朗读、收藏、重新翻译；
- 可折叠侧栏：字典、历史、详情。

### 5.4.3 历史页

- 左侧：日期/类型筛选；
- 中间：历史列表；
- 右侧：翻译详情；
- 支持单击恢复到翻译页。

## 5.5 V2 本地存储建议

若当前项目未建立统一持久化层，推荐使用 SQLite。

### 建议表

```text
translation_history
dictionary_cache
favorites
app_settings
```

### 基本要求

- 所有写入必须异步，不能阻塞渲染线程；
- 支持数据库版本迁移；
- 历史原文和译文建立全文或前缀搜索能力；
- 缓存应具备过期和容量控制；
- 用户清除历史后，应同时处理关联收藏之外的数据。

## 5.6 V2 性能指标

以下指标以“模型已加载”的参考环境为准：

| 指标 | 目标 |
|---|---|
| 划词后 UI 出现 | ≤ 150ms |
| 翻译请求状态反馈 | ≤ 100ms |
| 本地模型首个流式输出 | 目标 ≤ 1.5s |
| 句段联动高亮 | ≤ 50ms |
| 本地字典缓存命中 | ≤ 100ms |
| 历史搜索 | 1 万条内 ≤ 200ms |
| 主窗口冷启动 | 目标 ≤ 2.5s |
| 浮窗关闭后残留 | 不允许存在幽灵窗口或无法交互区域 |
| 句段对照额外模型体积 | 0 MB，不引入专用对齐模型 |

模型速度受设备和模型影响，因此应区分：

- UI 响应性能；
- 模型推理性能；
- 冷启动性能；
- 热启动性能。

## 5.7 V2 埋点与本地诊断

默认不上传用户文本。

允许记录匿名本地指标：

- 翻译请求成功率；
- 平均首字时间；
- 平均完成时间；
- 结构化解析失败次数；
- 字典命中率；
- 文本清理回退次数；
- 浮窗打开和关闭异常。

诊断日志必须支持：

- 一键导出；
- 自动脱敏；
- 不记录完整原文和译文；

# 6. V3 PRD：LLM 翻译工作台

## 6.1 V3 目标

V3 在 V2 的基础上，将 LexiFlow 从“快速翻译工具”升级为“可控制的 LLM 翻译工作台”。

重点解决：

1. 用户无法方便地调整局部译文；
2. 专业术语缺少稳定约束；
3. 截图、Markdown、字幕等内容仍需借助其他工具；
4. 不同场景需要不同翻译策略，但当前配置粒度不足；
5. 词典、翻译结果和命名功能之间缺少上下文联动。

## 6.2 V3 非目标

V3 暂不实现：

- 大规模云端协作；
- 企业翻译项目管理；
- CAT 工具完整替代；
- Word/PPT 像素级排版还原；
- 实时视频字幕翻译；
- 手机端 AR 翻译；
- 人工译员订单平台；
- 全功能语言学习平台；
- 逐词或短语级精细语义对齐；
- 内置 mBERT、XLM-R、awesome-align 等专用对齐模型和额外推理运行时。

#### 远期实验项

短语级语义对齐不进入 V2/V3 正式范围。后续仅在以下条件同时满足时重新评估：

- 用户研究证明句段级对照仍不能满足核心阅读场景；
- 存在体积、速度和准确率均可接受的轻量实现；
- 不增加基础安装包体积，模型可作为可选组件下载；
- 对齐失败能够稳定回退，不影响核心翻译流程。

## 6.3 V3 功能范围


### P0-1：局部重新翻译

#### 需求说明

用户可以对单个句段或局部短语发起重新翻译，而无需重新请求全文。

#### 预设操作

- 更自然；
- 更正式；
- 更简洁；
- 更口语；
- 更直译；
- 保持原句结构；
- 使用指定词语；
- 自定义要求。

#### 交互流程

1. 用户选中某句或某段译文；
2. 点击“重新表达”；
3. 选择预设或输入要求；
4. 显示候选结果；
5. 用户确认后替换；
6. 保留原始版本，可撤销。

#### 数据要求

```ts
interface SegmentRevision {
  id: string;
  segmentId: string;
  previousTarget: string;
  newTarget: string;
  instruction: string;
  createdAt: number;
}
```

#### 验收标准

- 只向模型发送必要上下文；
- 修改后其他句子不改变；
- 支持撤销和恢复；
- 替换后全文译文自动重组；
- 用户可以查看原译文。

---

### P0-2：备选译法与表达比较

#### 需求说明

用户主动请求时，为当前句段提供多个候选译法。

#### 默认候选

- 推荐译法；
- 直译；
- 自然表达；
- 正式表达。

#### 展示要求

每个候选可附带简短说明：

```text
推荐译法：兼顾准确性和自然度
直译：尽量保留原文结构
正式表达：适合论文、报告和正式文档
```

#### 约束

- 不默认同时生成多个译文；
- 仅处理当前句段；
- 候选数量默认 3 个，最多 5 个；
- 选择候选后可撤销；
- 备选结果可缓存。

### P0-3：术语表

#### 需求说明

允许用户建立本地术语表，确保技术、论文和行业内容中的关键术语保持一致。

#### 术语字段

```ts
interface GlossaryEntry {
  id: string;
  sourceTerm: string;
  targetTerm: string;
  sourceLanguage: string;
  targetLanguage: string;
  domain?: string;
  caseSensitive: boolean;
  matchMode: "exact" | "word" | "phrase";
  note?: string;
  enabled: boolean;
  createdAt: number;
  updatedAt: number;
}
```

#### 功能要求

- 新增、编辑、删除、启用和停用；
- 支持 CSV 导入导出；
- 支持按领域分组；
- 翻译前检测命中术语；
- 提示词中注入命中项，而非全部术语；
- 翻译后校验术语是否被正确使用；
- 对术语冲突给出提示；
- 可从翻译结果或字典卡片一键加入术语表。

#### 验收标准

- 术语命中可在结果中标记；
- 仅注入当前文本相关术语；
- 禁用术语不参与翻译；
- CSV 导入具备字段校验；
- 相同源词冲突时有明确优先级规则；
- 术语表完全本地保存。

### P0-5：截图 OCR 翻译

#### 第一阶段范围

- 全局快捷键进入截图；

- 展示识别原文；
- 调用现有翻译流程；
- 展示原文与译文；
- 点击 OCR 文本块时，高亮截图对应区域。

#### 数据结构

```ts
interface OcrBlock {
  id: string;
  text: string;

    x: number;
    y: number;
    width: number;
```

#### 实现原则

- OCR 失败时可以保留截图并重新识别；
- 不在 V3 第一阶段进行译文覆盖原图。

#### 验收标准

- 多屏幕和缩放环境下框选坐标正确；
- OCR 文本块与截图位置一致；
- 用户可复制 OCR 原文；
- 用户可手动修正识别结果；
- 截图默认不永久保存；
- 关闭窗口后临时截图按设置清理。

### P0-6：轻量文档翻译

#### V3 支持格式

- TXT；
- Markdown；
- SRT；
- 纯文本型 PDF；
- 常见代码和配置文件的只读翻译预览。

#### 核心要求

- 保留段落结构；
- 保留 Markdown 标记；
- 不翻译代码块；
- 不破坏链接；
- SRT 时间轴保持不变；

- 纯译文 TXT；
- 双语 Markdown；
- 翻译后 Markdown；
- 翻译后 SRT；

#### 验收标准

- 处理过程中实时展示进度；
- 取消后不再继续调用模型；

- 单个分块失败不导致全部结果丢失；

6. 手工验收步骤；
7. 已知限制；
8. 截图或录屏证明；
9. 不允许顺带重构无关模块；
10. 不允许在无测试保护的情况下大规模修改现有翻译流程。

建议每个功能拆分为独立任务和独立提交，提交示例：

```text
feat(translation): add structured segment result
feat(segment-sync): add sentence-clause hover synchronization
feat(dictionary): add local dictionary provider
feat(history): persist translation history in sqlite
feat(cleanup): normalize copied pdf text
```

# 10. 最终产品形态

V2 完成后，LexiFlow 应达到：

> 用户选中文本后，可以快速获得译文，并通过句子对照、字典、历史和快捷操作完成日常阅读翻译。

V3 完成后，LexiFlow 应达到：

> 用户不仅可以得到译文，还可以通过稳定的句段对照理解上下文、控制术语和表达、局部调整结果，并完成截图和轻量文档翻译。

产品核心始终保持：

- 本地优先；
- 快速响应；
- 界面克制；
- 翻译可理解；
- 结果可控制。
