# 语音、单词本与桌面入口完善

状态：`completed`  
创建：2026-08-23  
完成：2026-08-23

## 背景

LexiFlow 原先仅在本地词典卡片中通过浏览器 `speechSynthesis` 提供英文单词发音，翻译结果、双语阅读与快速翻译窗没有朗读控制。应用也没有独立单词本，用户无法把词典结果或句段中的生词保存、标记掌握并集中复习。划词提示使用 26×26 透明 SVG 与 28×28 透明窗口，边缘与命中区域不一致；默认 `Ctrl+Alt+T/N/S` 容易与 VS Code 等开发工具冲突。全局快捷键依赖 LexiFlow 进程，原有开机启动默认关闭，导致未手动启动应用时快捷键不可用。

## 目标

- 翻译工作台、双语阅读、快速翻译窗和词典共用可停止、可感知状态的本地系统朗读。
- 用户可从词典结果保存生词，并在单词本中搜索、编辑释义/笔记、朗读、标记已掌握或重新学习、删除。
- 单词本数据本地持久化，纳入 schema 校验、隐私清除、浏览器预览和自动测试。
- 划词提示图标在透明悬浮窗中完整显示且命中区域与视觉一致。
- 新安装使用低冲突快捷键并默认随 Windows 登录后台启动；设置页明确说明后台常驻与完全退出的差异，快捷键注册失败能反馈给用户。

## 范围

### 包含

- 基于现有 `speechSynthesis` 的 TTS 朗读，不发送用户内容、不新增远程调用。
- 独立单词本领域契约、存储、应用服务、IPC、页面与词典入口。
- 划词提示窗口/资源修复、快捷键默认值和设置说明。
- 相关单元测试、E2E 覆盖、用户与架构文档更新。

### 不包含

- 麦克风录音、语音转文字和 Whisper 模型分发；该能力涉及新模型访问、权限与大体积资源，应作为后续独立计划。
- 间隔重复算法、账号同步或云端单词本。
- 进程完全退出后仍捕获全局热键；Windows 全局热键需要常驻进程，本次通过开机启动和关闭到托盘保证日常可用性。

## 方案与影响面

- 将词典专用朗读模块泛化为共享语音控制器，支持语言匹配、分段队列、停止、异步 voice 列表与订阅；不新增 IPC。
- 新增 `VocabularyEntry` 与版本化 `VocabularyFile`，由主进程 `VocabularyStore` 持久化到 `vocabulary.json`，所有变更经可信 IPC sender 校验与 DTO 解析。
- 同步更新 `IPC_CHANNELS`、`TranslatorApi`、preload、领域 registrar、`register-all` 和浏览器预览适配器。
- 单词本只保存用户主动加入的单词、释义、音标、上下文和笔记；诊断不导出正文，隐私清除会清空单词本。
- 新默认快捷键使用三修饰键组合，降低与编辑器常用组合冲突；已有自定义值不迁移覆盖。新安装及仍使用旧默认快捷键的升级安装默认开机启动，主窗口关闭仍隐藏到托盘。

## 风险与回滚

- 风险：Windows 系统语音包可能缺失或 voice 列表延迟加载；UI 会显示不可用状态且不阻断翻译。
- 风险：新增本地数据需保证损坏文件隔离与隐私清除；使用既有 `JsonStore` 备份/校验机制并有自动测试覆盖。
- 风险：全局快捷键是否被第三方占用只能在运行时确认；注册失败会保留原快捷键并显示明确错误。
- 回滚：语音为 Renderer/共享控制器增量；单词本使用独立文件和独立 IPC，可分别移除而不影响翻译历史、术语表与 Provider 配置。

## 结果与遗留

- 结果：完成本地 TTS、生词本全链路、划词提示修复，以及低冲突且支持后台常驻的快捷键体验；同步更新产品、架构、开发、用户、排障和发布文档。
- 遗留：发布前需在目标 Windows 机器试听已安装的中英文语音，并与 VS Code 同时运行进行人工快捷键验收；麦克风输入、语音转文字、间隔重复和云同步不在本次范围。
